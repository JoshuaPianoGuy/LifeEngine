# LifeEngine — Experiments: Design & Implementation Reference

This document describes **what the experiments are, what they measure, and exactly how they run** — from the shared simulation substrate up to the individual SLURM job arrays and the analysis scripts that consume their output.

> **Relationship to other docs.** `MATHEMATICAL_REFERENCE.md` derives the RL/GA/energy math in depth and is still the best reference for the *equations*, but several of its **constants are from an earlier design** (single founder, top‑5 crossover, mutation disabled, hidden‑size 8, 33‑input network). This file documents the **current** implementation and the values actually used by the experiments. Where they disagree, this file wins. `HEADLESS.md` covers the headless runner in general; here we focus on the experiment set.

---

## 1. The research question

The project studies **three ways an agent population can acquire adaptive behaviour** in the same predator‑laden foraging world, and compares them head‑to‑head:

| Condition | Mechanism | Heritable unit | "Lamarckian?" | Code |
|-----------|-----------|----------------|---------------|------|
| **Evolution** | Genetic algorithm only — no within‑life learning | `genome_weights` | n/a (no learning) | `GAManager` (`--condition evolution`) |
| **Learning** | GA **plus** in‑lifetime REINFORCE | `genome_weights` | **No** — RL adapts `active_weights` within a life for behaviour, but only the frozen genome is selected/inherited; learned drift dies with the organism (a Baldwin‑effect setup) | `GAManager` with `rl_enabled` (`--condition learning`) |
| **Pure RL** | In‑lifetime REINFORCE only — no GA | `active_weights` | **Yes** — learned weights are synced into the genome at reproduction and reseed the population, so learning persists and propagates | `PureRLManager` (`--mode pure_rl`) |

All three share **identical** world physics, energy rules, predators, food, day/night, network architecture, and generation timing. They differ **only** in the adaptation mechanism, so any behavioural or fitness difference is attributable to *learning vs evolution vs their combination*.

## 2. The shared simulation substrate

Everything in this section is common to all conditions.

### 2.1 World, grid, and seeded maps

* The world is a 2‑D grid of cells (`--width` × `--height`; the comparison experiments use **500 × 500**). Cells hold terrain, food, walls, caves, organisms and predators.
* Terrain is **deterministic in a seed**. Each `--map-seed N` maps to a **pool of 50 maps** generated by `src/maps/generateMapPool.js`. On first use, `WorldEnvironment._loadMapPool()` generates the pool and caches it atomically to `src/maps/map_pool_seed<N>.json`; every later run (any condition) reuses that same file, so **all conditions see identical terrain for a given seed**.
* **Only the terrain is seeded.** GA mutation, RL exploration, reproduction chance and predator wandering all use unseeded `Math.random()` — deliberately, so each run is an independent sample of stochastic dynamics on a fixed world.

### 2.2 Generation and episode structure

Timing is single‑sourced in `GenerationConstants.js` (so the epsilon‑decay horizon can never drift from the generation length):

```
TICKS_PER_MAP = 2000      MAPS_PER_GEN = 5      TICKS_PER_GEN = 10 000
```

A **generation** is one continuous **10 000‑tick** episode for the whole population, presented as **5 different maps of 2 000 ticks each, shown in sequence**. Across a map boundary within a generation the population **persists with the same energy and position** — only the terrain changes and RL eligibility traces reset (`startNextMap()`). The 5‑map curriculum stops a generation from over‑fitting a single terrain. At the end of the 5th map the manager runs its end‑of‑generation step (GA selection, or the pure‑RL window close) and the next generation begins.

`--generations N` runs N such windows (the comparison runs use **1000**; the LR/epsilon sweeps use **500**).

### 2.3 The organism: body, energy, day/night, caves

* **Body / anatomy.** Every experimental organism is spawned with a **fixed anatomy** (one mover, four eyes at the corners facing outward, five mouths). Anatomy does **not** mutate — only the network weights do — so the network's input/output dimensions stay constant and are directly comparable across organisms.
* **Energy.** `START_ENERGY = 300`, `ENERGY_CAPACITY = 500`. Every `ENERGY_DECAY_INTERVAL = 10` ticks the organism loses `ENERGY_DECAY_RATE = 1 ×` a location/time multiplier. Death occurs when energy ≤ 0 (or the practically‑unreachable `MAX_LIFETIME = 1 000 000` cap — in practice lifespan is bounded by energy and the generation window).
* **Day/night cycle.** `day_length = night_length = 300` ⇒ a **600‑tick** cycle; it is night when `total_ticks % 600 ≥ 300`. The decay multiplier couples time‑of‑day with caves:
  * Day, outside cave: ×1 (normal)
  * Day, inside cave: **×2** (caves are costly by day — not a free refuge)
  * Night, inside cave: **×0** (safe sleep — energy frozen)
  * Night, outside cave: **×2** (dangerous to be exposed at night)

  So organisms are pressured to forage by day and shelter in caves at night, and to time cave use correctly.
* **Caves** are also **predator‑safe** (see §2.7): predators cannot enter cave cells and won't target prey standing in one.

### 2.4 Food tiers and fitness

Food comes in tiers with different energy/score values (`MouthCell.FOOD_ENERGY_VALUES`): base `food` 0.01, **low 0.5, medium 1.0, prestige 2.0**. Eating adds the value to energy (capped at 500) and to the organism's `cumulative_food_score`.

**Fitness = `cumulative_food_score`** — the total food value an organism consumed over its life. This is the GA's selection signal and is **independent of the RL reward**, so learning and evolution are compared on the same yardstick. Prestige food is worth the most but is guarded by patrol predators when those are enabled.

### 2.5 Reproduction and death

* **Within‑life asexual reproduction** is **energy‑triggered**: once an organism has gained ≥ **3.5** energy since its last reproduction (`energyGainedSinceReproduction`), it spawns a child (with `REPRODUCTION_SUCCESS_RATE = 0.8`) near the central spawn point. This grows the population within a generation and adds a second selection pressure (ability to net surplus energy).
* **Inheritance depends on condition** (this is the crux):
  * **GA conditions (evolution, learning):** children inherit the parent's **`genome_weights` only** (non‑Lamarckian) plus a small asexual mutation (`ASEXUAL_MUT_PROB = 0.05`, `σ = 0.1`). Any RL drift in the parent's `active_weights` is **not** passed on.
  * **Pure RL:** the parent's learned `active_weights` are **synced into the genome** before the child is created, so children inherit what the parent *learned* (Lamarckian continuity).
* **Death:** energy ≤ 0. Dead organisms are removed; their `death_cause` is logged (`starved`, `drained` by a predator, or `survived` = still alive at generation end).

### 2.6 The neural policy (senses → network → action)

Each organism is driven by a small feed‑forward network (`NNBrain`), the same architecture in every condition:

```
Input (54) → ReLU hidden (64) → softmax output (6)
```

* **Inputs (54):** 4 eye directions × **13 percept types** + **2 scalar inputs** (e.g. normalised energy). The 13 percepts (see `PERCEPT_INDEX` in `NNBrain.js`) cover the food tiers, terrain/walls, caves, roaming and patrol predators, and food "landmarks". Prey have **no sensory channel for predators beyond the eye percepts** — detection is one‑directional (predator→prey).
* **Hidden:** `HIDDEN_SIZE = 64` (tunable via `--hidden-size`; changing it resizes the genome).
* **Output (6):** softmax over `up, right, down, left, rotate‑left, rotate‑right`.
* **Genome size** = `61·H + 6` weights (`W1 = 54H`, `b1 = H`, `W2 = 6H`, `b2 = 6`); with `H = 64` that is **3910** weights. Every organism carries two copies: `genome_weights` (heritable) and `active_weights` (what it acts on; RL updates these).

Action selection is **epsilon‑greedy over the softmax** (see §3.2 for how epsilon and REINFORCE interact).

### 2.7 Predators

Predators are a fixed environmental hazard, not part of the evolving population (`PredatorHyperparameters.js`, `PredatorManager`):

* **Roaming predators:** a **fixed count** (`--roaming-predators`, **60** in the comparison/sweeps) wander and chase prey within a detection radius (25 cells at the 400‑col reference, rescaled to the actual grid), giving up beyond 35. On contact, each drain‑cell removes `--predator-drain` energy **per tick** from the prey (**5** in the comparison/sweeps) and applies an RL reward penalty. Predators never die or reproduce — the count is held constant for the whole run.
* **Patrol predators:** guard prestige‑food patches (`--predators-per-patch`), leashed to their patch. **Disabled** in the comparison and LR/epsilon experiments (`--predators-per-patch 0`) so roaming predation is the only predator variable.
* **Caves are safe** from both predator types (movement‑ and targeting‑level).

## 3. The three adaptation mechanisms in detail

### 3.1 Evolution — `GAManager` (`--condition evolution`)

No within‑life learning (`rl_enabled = false`; `active_weights === genome_weights`, so drift is exactly 0). At the end of each generation `evolve()` runs:

1. **All agents are eligible.** The entire generation — the 100 founders plus every descendant that lived — forms the selection set. There is **no truncation and no elitism cutoff**: every agent has a non‑zero chance of being selected. (The set is sorted by fitness only for bookkeeping.)
2. Optional **natural‑disaster cull** removes a random, fitness‑blind slice of the eligible set *before* selection (off by default — see §4).
3. **Tournament selection** (`TOURNAMENT_K = 2`): to make each of the `POPULATION_SIZE = 100` next‑generation founders, pick two parents; each parent is the fitter of **2 agents sampled uniformly at random from the whole eligible set**. Selection pressure is set purely by the tournament size `k`, not by a hard fitness cutoff.
4. **Uniform crossover** (each weight 50/50 from parent A or B, clipped to [−1, 1]).
5. **Gaussian mutation** (`MUT_PROB = 0.03` per weight, `MUT_SIGMA = 0.1`).
6. **No elitism** — every founder is a fresh crossover child. New founders spawn at the world centre.

> `SELECTION_PERCENT = 0.2` is **not** a selection cutoff — it only defines the top‑20% cohort used for *reporting* (`top20percent_fitness` and the top‑cohort drift/variance in `generations.csv`). Parent selection always uses the full population.

### 3.2 Learning — `GAManager` + REINFORCE (`--condition learning`)

Identical GA machinery to §3.1, **plus** every organism runs **REINFORCE with eligibility traces** each tick, updating its `active_weights` (not the genome). The genome stays frozen through life and is the only thing the GA selects/inherits — so learning shapes *behaviour and survival* within a life, but evolution still searches genome space (Baldwin effect, **non‑Lamarckian**).

**Per‑tick reward** (`AdvancedOrganism`):

```
r = food_value_eaten                    (0.5 / 1.0 / 2.0 by tier)
  + EXPLORE_BONUS (0.15)  on first visit to a new cell
  − DECAY_PENALTY (0.05)  × energy lost to decay this tick
  − PREDATOR_DRAIN_PENALTY (0.5)  while being drained
```

**REINFORCE update** on `active_weights` using eligibility traces (`TRACE_DECAY = 0.90`), a running‑mean **baseline** (EMA decay 0.9) to reduce variance, and **importance weighting** to correct for exploration:

* Action is drawn epsilon‑greedily: with prob. ε take a *uniform random* action; else sample from the softmax π. The behaviour policy is therefore the mixture `b(a) = (1 − ε)·π(a) + ε/N` (N = 6 actions).
* The update is scaled by the **importance ratio** `ρ = π(a) / b(a)` for the action actually taken (capped at 10 for stability), so off‑policy exploration noise doesn't bias the gradient. When `--no-epsilon` is set (`epsilon_enabled = false`), ε is pinned to 0 for the whole life, the organism samples straight from π, `b = π`, and **ρ = 1** (pure on‑policy REINFORCE). Epsilon‑greedy is applied **only** in RL conditions — the evolution condition always acts on‑policy.

> **All production runs are `--no-epsilon`, so learning is fully on‑policy.** With ε = 0 the importance ratio is identically ρ = 1 — the importance‑sampling code stays in place but is a **no‑op** (it only ever did anything for the earlier epsilon LR‑sweep runs). What remains active are the two *standard on‑policy* REINFORCE components: the **running‑mean baseline** `r − b̄` (variance reduction) and the **eligibility traces** (`γ = 0.90`, temporal credit assignment). So "on‑policy" here still means REINFORCE‑with‑baseline‑and‑traces, not baseline‑free vanilla REINFORCE. The per‑tick update reduces to `w ← clip(w + α·(r − b̄)·e, [−1,1])` with `e_t = γ·e_{t−1} + (𝟙[k=a] − π_k)·∇`.

**Epsilon schedule.** ε is **per organism**: each starts at `epsilon_start` (default 0.3; sweeps use 0.2/0.3/0.5/0.7) at birth and decays to `epsilon_end` (0.05) over its own age fraction `t_age / (TICKS_PER_GEN − birth_tick)` — the denominator is that organism's *maximum achievable lifespan* (the generation ticks remaining when it was born, `_max_possible_lifetime`), **not** a flat `TICKS_PER_GEN`. This way a late‑born organism still completes the full 0.3→0.05 sweep over its shorter life instead of dying while still highly exploratory. The decay is shaped by `epsilon_decay_shape`:

* `sublinear` (exponent 0.5, √): drops fast early, flattens late — explore‑early.
* `linear` (exponent 1): constant‑rate.
* `quadratic` (exponent 2, default): holds high then drops late — explore‑late.

**Operating point (going forward).** The learning condition runs **no‑epsilon** (pure on‑policy REINFORCE), with the learning rate chosen per environment from its LR sweep: **LR 0.01 in the predator‑free *baseline* environment**, and **LR 0.02 in the *roaming‑predator* environment** (60 predators, drain 5). Pure‑RL mirrors the learning condition's RL settings in whichever environment it is compared in.

### 3.3 Pure RL — `PureRLManager` (`--mode pure_rl`)

REINFORCE only — **no GA, no fitness‑based selection**. Adaptation comes from (1) within‑life RL, (2) energy‑triggered reproduction where the child inherits the parent's **learned** weights (Lamarckian: `active → genome` synced at birth), and (3) an optional undirected between‑episode mutation. Population management at each 10 000‑tick window boundary (`closeWindow()`):

* **Cap down** to `POPULATION_SIZE = 100` if reproduction overshot (random removal — no fitness signal).
* **Between‑episode mutation** of survivors (undirected Gaussian, see table below).
* **Log the window** (so metrics reflect only the organisms that actually lived it).
* **Top up to 100** from a rolling **buffer** of the last `COLLAPSE_BUFFER_SIZE = 25` dead organisms' learned weights: each refill organism is a **random** buffer sample, **mutated** around. This keeps every window starting at a full 100 (comparable to the GA conditions' 100 founders); a full extinction is just the "deficit = 100" case.

The buffer‑and‑mutate design means learned structure is never thrown away on a collapse, but the refilled population is a diverse cloud around past strategies rather than clones.

### 3.4 Mutation consistency across conditions

All three conditions use the **same two mutation kernels** (verified identical so the comparison is controlled):

| Kernel | When | Probability / σ | Source |
|--------|------|-----------------|--------|
| **Intra‑generation** | asexual reproduction (all conditions) | 0.05 / 0.1 | `AdvancedOrganism._mutateGenome` (shared) |
| **Inter‑generation** | GA between‑gen mutation; pure‑RL between‑episode + top‑up | 0.03 / 0.1 | `ExperimentParams.mut_prob/mut_sigma` (honours `--mut-prob/--mut-sigma`) |

## 4. Optional stressors (knobs, off in the core comparison)

* **Predator drain / count** (`--predator-drain`, `--roaming-predators`, `--predators-per-patch`) — the predation‑pressure levers. Swept by the predator/patrol experiments.
* **Natural disasters** (`--disaster …`) — an optional mass‑mortality event that culls a fixed fraction of the selection pool before GA selection, on random generations (Bernoulli `disaster_prob`), driven by a dedicated reproducible PRNG. A gradual‑recovery variant tapers the culled fraction over generations. Off in the core comparison; swept by the disaster experiments.

## 5. The experiments (SLURM job arrays)

Each experiment is a SLURM **job array**: one array task per point in the factor grid, each task invoking `src/headless.js` once (or looping a few runs). All target the CHPC ada partition, Node 16, and write to `logs/`. Submit with `sbatch <file>` from the code directory; per‑job hyperparameters can be overridden with environment variables (e.g. `GENERATIONS=200 sbatch …`).

### 5.1 Three‑condition comparison (the main experiment)

500 × 500 world, **1000 generations**, **60 roaming predators, drain 5**, patrol off, **5 seeds** (`1 42 999` + new `123 456`). One array task per seed (`--array=0-4`).

| Script | Condition flags | Output tree |
|--------|-----------------|-------------|
| `run_learning_condition_roaming_array.slurm` | `--condition learning --mode standard --no-epsilon --learning-rate 0.02` | `logs/learning/standard/auto-run/roam60d5_g1k_learning_…` |
| `run_evolution_condition_roaming_array.slurm` | `--condition evolution --mode standard` (no RL knobs) | `logs/evolution/standard/auto-run/roam60d5_g1k_evolution_…` |

The two RL‑using conditions share identical hyperparameters (no epsilon, LR 0.02 in this roaming environment), so **learning vs pure‑RL isolates the GA's contribution**, and **learning vs evolution isolates within‑life learning**. LR 0.02 / no‑epsilon were selected from the LR sweep below.

## 6. How a single run executes (`src/headless.js`)

1. **Parse flags** and `ExperimentParams.applyOverrides(...)` **before** any sim module loads (so `hidden_size`, mutation rates, epsilon, LR bake into `NNBrain`/`GAManager`/`PureRLManager` at module‑load time).
2. Set `WorldConfig` (seed, grid, `learning_enabled = (condition === 'learning')`, `experiment_mode`), copy predator knobs onto `PredatorHyperparameters`.
3. Build the world: `new WorldEnvironment()` → `generateWorld()` (loads/creates the seed's map pool) → `ga_manager.spawnGeneration()` (100 founders at centre) → `predator_manager.spawnAll()`.
4. Resolve a collision‑proof run directory from `--run-name` (else `PBS_JOBID`), under `logs/<condition>/<mode>/auto-run/<run-name>/`, and write `params.json` + `params.txt` (the full resolved parameter set).
5. **Main loop:** tick the world until `generations × 10 000` ticks. Each tick, the active manager (`GAManager`/`PureRLManager`) advances the map/generation lifecycle (`NEXT_MAP` → new terrain + keep population; `NEXT_GENERATION` → `evolve()`; pure‑RL `NEXT_WINDOW` → `closeWindow()`), and predators tick every update.
6. **Finalise:** flush the logger; print totals.

Because overrides bake in at module load, a run is fully described by its `params.json`.

## 7. Running in the browser (`src/BrowserPreset.js`)

The browser build runs the **same** experiment code as the cluster (same managers, map pool, predators, logger) but has no CLI, so it cannot call `ExperimentParams.applyOverrides`. Instead **`src/BrowserPreset.js`** — imported on the first line of `src/index.js`, before `Engine` — applies one named preset at startup. It mirrors the §5.1 SLURM scripts, so a browser run is directly comparable to a cluster run.

### 7.1 Configuring a run

Edit the constants at the top of `src/BrowserPreset.js` and rebuild:

```js
const CONDITION   = 'learning';   // 'learning' | 'evolution' | 'pure_rl'
const ENVIRONMENT = 'hard';       // 'baseline' | 'hard'
const MAP_SEED    = 1;            // 1 | 42 | 999 | 123 | 456
const GRID_COLS   = 500;          // 500x500 matches every cluster run
const GRID_ROWS   = 500;
```

```bash
node generate_map_pool.js --seed <MAP_SEED>   # ONLY when MAP_SEED changes
npm run build                                 # or npm run build-watch
npm run serve                                 # http://localhost:3000
```

Everything else is derived from the preset tables, which encode the SLURM flags:

| `ENVIRONMENT` | Learning rate | Roaming predators | Drain | Patrol | Equivalent flags |
|---------------|---------------|-------------------|-------|--------|------------------|
| `baseline` | **0.01** | 0 | 1.0 (inert) | 0 | `--roaming-predators 0 --predators-per-patch 0` |
| `hard` | **0.02** | 60 | 5 | 0 | `--roaming-predators 60 --predator-drain 5 --predators-per-patch 0` |

| `CONDITION` | `learning_enabled` | `experiment_mode` | Manager | Equivalent flags |
|-------------|--------------------|-------------------|---------|------------------|
| `learning` | `true` | `standard` | `GAManager` (RL on) | `--condition learning --mode standard` |
| `evolution` | `false` | `standard` | `GAManager` (RL off) | `--condition evolution --mode standard` |
| `pure_rl` | `true` | `pure_rl` | `PureRLManager` | `--condition learning --mode pure_rl` |

Epsilon is forced **off** in every preset (`epsilon_enabled = false`), matching the production `--no-epsilon` runs. An unrecognised `CONDITION` / `ENVIRONMENT` throws at startup with the valid list rather than silently running a wrong configuration.

### 7.2 Why the preset exists (and what NOT to edit)

`NNBrain`, `AdvancedOrganism` and `GAManager` read their constants from `ExperimentParams` **at module load**, so the preset must be evaluated first. That is why `src/index.js` imports it above `import Engine`: ES import declarations are hoisted but evaluate in source order, and `BrowserPreset` requires only the three leaf config modules (no simulation code).

Configuring a browser run previously meant hand-editing three files, and missing any one of them — usually `patrol.predatorsPerPatch`, which every production run disables — silently produced a run that did not match the cluster results it was being compared against. With the preset in place, **editing these fields directly now has no effect in the browser**; change `BrowserPreset.js` instead:

| File | Preset-owned (do not edit for a browser run) | Still edited here |
|------|---------------------------------------------|-------------------|
| `src/WorldConfig.js` | `learning_enabled`, `experiment_mode`, `MAP_SEED`, `MAP_COLS`, `MAP_ROWS` | everything else |
| `src/ExperimentParams.js` | `learning_rate`, `epsilon_enabled` | mutation, disaster, food-shuffle, `hidden_size`, `population_size`, … |
| `src/Organism/PredatorHyperparameters.js` | `count`, `drainAmount`, `patrol.predatorsPerPatch` | radii, leash, move intervals (fixed design, not swept) |

The preset is imported **only** by `src/index.js` (the webpack entry point), so `src/headless.js`, the `src/eval` probe harness and the landscape tooling are unaffected — they keep configuring themselves from their own flags.

### 7.3 Reading back what is running

The browser writes **no `params.txt`** (unlike §6 step 4), so two readouts stand in for it:

* **About tab** — `ControlPanel.renderRunConfig()` renders condition, environment, RL settings and map seed / grid into the panel.
* **Devtools console** — a `[BrowserPreset] …` banner at startup, e.g.
  `condition=learning (learning_enabled=true, mode=standard) environment=hard lr=0.02 epsilon=off predators: roaming=60 drain=5 patrol=0 map_seed=1 grid=500x500`

Check one of them before comparing a browser run against cluster results. `WorldEnvironment` separately warns if the bundled `map_pool.json` was generated for a different seed than `MAP_SEED`.

### 7.4 Limits vs. the cluster runs

* **No generation cap** — the browser runs until you stop it; there is no `--generations` equivalent.
* **CSV output requires `npm run serve`** (not opening `dist/index.html` directly): `server.js` receives the logger's POSTs and writes to `logs/<condition>/<mode>/auto-run/run_N/`, the same layout as headless.
* **Genome logging** (`--log-genomes`) is not exposed by the preset.
* **Speed** — a 500x500 world in a browser is far slower than a headless cluster task; the browser build is for inspecting behaviour, not for producing comparison data.

## 8. Outputs / logging schema (`src/Logger.js`)

Each run directory contains:

* **`params.json` / `params.txt`** — the authoritative resolved parameters (seed, condition, mode, grid, generations, LR, epsilon, mutation, predators, …). **Analysis scripts key off `params.json`, not folder names.**
* **`generations.csv`** — one row **per generation** (population‑level): `avg_fitness`, `top20percent_fitness`, `best_fitness`, `peak_population`, `total_agents`, `avg_lifetime`, `avg_learned_weight_diff` (MAD — mean |active − genome|, the learning signal, ~0 in evolution), `avg_network_weight_mag` (RMS), `disaster_cull_frac`, etc.
* **`organisms.csv`** — one row **per organism per generation** (it logs **every** organism that lived that generation — its row count per generation equals `total_agents`, up to a 20 000 cap; the `top20pct_log` variable name is a misnomer). Columns: `rank`, `fitness`, `lifetime`, `energy_at_death`, `death_cause`, `cumulative_food_score`, `food_{low,medium,prestige,default}`, `cells_visited`, `predator_touches`, `drained_ticks`, `cave_entries{,_day,_night}`, `learned_weight_diff`, `network_weight_magnitude`.
* **`events.csv`** — timestamped lifecycle events (generation close, disasters, pure‑RL collapse/top‑up, …).

## 9. Analysis scripts

All are standalone `python analyse_*.py` scripts (matplotlib, Agg backend) that discover runs via `params.json`, aggregate across seeds (mean ± std), and write PNGs + a summary CSV under `output/`.

* **`analyse_lr_sweep_noeps.py` / `analyse_lr_sweep_epsilon.py`** — the LR tuning (§5.2). Fitness, top‑20%, population, and MAD over generations and as final‑window endpoints per seed; epsilon version panels by decay shape with a line per LR.

All population‑averaged then averaged across seeds.
* **`analyse_lr_sweep.py` / `analyse_lr_sweep_learning.py` / `analyse_lr_sweep_behaviour.py`** — earlier LR‑sweep views (fitness / learning diagnostics / behaviour).
* **`analyse_epsilon_sweep.py`, `analyse_predator_sweep.py`, `analyse_predator_metrics.py`, `analyse_disaster_sweep_evolution.py`, `analyse_weights*.py`, `compare_weights.py`** — the other sweeps / diagnostics.

## 11. Reproducibility notes

* **Seeded:** only map terrain (`--map-seed`) and, optionally, the disaster PRNG (`--disaster-seed`). A seed fixes the 50‑map pool identically for every condition.
* **Unseeded (deliberate):** GA mutation, RL exploration, reproduction chance, predator wandering. Multiple seeds × the across‑seed aggregation in the analysis scripts capture this stochasticity.
* **Fully recorded:** every run's resolved parameters are in its `params.json`, and overrides bake in at module load, so a run is reproducible up to the unseeded `Math.random()` draws (and statistically reproducible across seeds).
